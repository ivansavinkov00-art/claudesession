# Промпт для Claude Code (облачная сессия): главная «Культура шитья», v2

## Для тебя, перед запуском (в Claude Code не копировать)

Заказчица одобрила дизайн v1. Дизайн-система (`DESIGN.md`), шапка, лента, подвал и окна остаются. Первый экран дорабатываем, не переделываем. Всё, что ниже первого экрана, строим по новой структуре.

| Файл | Что это |
|---|---|
| `PROMPT.md` | этот файл |
| `materials/texts.md` | все тексты v2, причёсанные; единственный источник текста |
| `materials/images.md` | 13 нумерованных слотов под картинки и промпты для Nano Banana |
| `materials/archive/PROMPT-v1.md` | прошлый промпт, для истории; Claude Code его не читает |
| `incoming/` | сюда складывать сгенерированные картинки |
| `.gitignore` | чтобы `node_modules` не попали в репозиторий |

1. **Репозиторий.** Облачная сессия работает с GitHub. Создай приватный репозиторий и залей в него папку проекта. В GitHub Desktop: File → Add local repository → выбрать папку → Publish repository (галочка «Keep this code private»).
2. **Скиллы.** В прошлый раз impeccable и design-taste-frontend ставились на твой компьютер, а не в папку проекта, поэтому облако их не увидит. Промпт написан так, что работает и без них. Claude Code попробует поставить их сам на шаге 0.
3. **Запуск.** На claude.ai/code выбери репозиторий. Доступ к сети оставь по умолчанию: его хватает для npm и GitHub. Напиши: «Прочитай PROMPT.md и выполни раздел „Промпт“».
4. **Результат** придёт на GitHub веткой с pull request. Смёржи его и подтяни изменения на компьютер (GitHub Desktop → Fetch origin → Pull).
5. **Картинки.** Генерируй по `materials/images.md`. Готовые файлы загружай в папку `incoming/` прямо на GitHub (Add file → Upload files). Номер слота ставь в начало имени: `01.png`, `07-platye.jpg`. Потом напиши в ту же сессию: «Новые картинки в incoming». Картинка, вставленная в чат, файлом в проекте не станет, поэтому только через `incoming/`.

# Промпт

## Контекст

Это продолжение проекта. В репозитории лежит прототип главной страницы сайта швейного производства «Культура шитья» (Челябинск), версия v1: `index.html`, `styles.css`, `script.js`. Заказчица одобрила визуальный язык v1. Задача v2 — перестроить главную под новую структуру и не сломать то, что одобрено. Финальный сайт соберут на Тильде. Весь интерфейс и тексты на русском.

**Не меняется:**

- Дизайн-система `DESIGN.md`: токены, гарнитуры Cormorant и IBM Plex Mono, радиус 0, «строчка», бирка, вертикальная лента, правило «одна нитка, два тона». Новые компоненты добавляй в DESIGN.md отдельным разделом «v2». Существующие правила не переписывай.
- Шапка, вертикальная лента справа, липкая кнопка на мобильном, подвал, окно «Куда отправить прайс», `privacy.html` и `consent.html`.
- Технологическая база: статика, vanilla JS, без фреймворков, CDN и сборки. Всё локально.

**Меняется:**

- Первый экран: доводка типографики и текста (см. «Экран 1»).
- Всё ниже первого экрана — новая структура. Блоки v1 «Два направления», «Полный цикл», «Собственный цех», «Посчитаем вашу партию» и окно `#calc` удаляются. Их содержание переезжает в новые экраны.
- Все картинки становятся нумерованными слотами 01–13 (см. «Картинки»).

## Материалы и приоритеты

Прочитай до начала работы:

1. `PROMPT.md` — этот файл.
2. `materials/texts.md` — все тексты v2. Текст берёшь только оттуда. Если чего-то не хватает, пиши `[уточнить]` и добавляй строку в README. Не выдумывай цифры, отзывы, клиентов, цены и сроки.
3. `DESIGN.md`, `PRODUCT.md` — система и контекст v1.
4. `materials/images.md` — слоты картинок.
5. `materials/brief.md` — бриф, для сверки фактов.

`materials/archive/` не читай.

Если требования конфликтуют, приоритет такой: этот промпт → texts.md → DESIGN.md → PRODUCT.md → бриф → скиллы.

Прежде чем писать код, покажи план на 15–20 строк: ASCII-схемы новых экранов (десктоп и 390px), список новых компонентов и что удаляешь из v1. Подтверждения плана не жди, сразу приступай.

## Скиллы и порядок работы

0. Если в проекте нет скиллов impeccable и design-taste-frontend, поставь их: `npx impeccable install` и `npx skills add https://github.com/Leonxlnx/taste-skill --skill design-taste-frontend`. Если за две попытки не получилось, работай без них: правила ниже самодостаточны.
1. Первым делом сними скриншоты текущего первого экрана «до»: `screenshots/v2/hero-before-{1440x800,1366x650,390x664,360x640}.png`.
2. impeccable в режиме доработки: PRODUCT.md и DESIGN.md уже есть, их не пересоздаёшь, а дополняешь.
3. design-taste-frontend: DESIGN_VARIANCE 6, MOTION_INTENSITY 5, VISUAL_DENSITY 4. В v1 движение было 3; теперь 5, потому что карусели и ховер-списку нужно движение. Остальная страница остаётся спокойной.
4. Порядок: заглушки картинок → структура и тексты всех экранов → интерактивные модули (калькулятор, карусель, список задач) → доводка первого экрана → проверка.
5. Проверка: `/impeccable critique` → `audit` → `harden` → `adapt` → `polish`. Всё найденное исправляй, а не просто перечисляй.

Больше всего работы в калькуляторе и карусели. Самое заметное — первый экран.

## Экран 1 — доводка, не редизайн

Этот экран одобрила заказчица. Сохрани: композицию (текст на 7 колонок, арка на 5), шапку, ленту, палитру, гарнитуры, формулировку H1 и три уровня в нём, лид, обе кнопки и бирку «Опт от 300 ед.».

Типографику доведи по принципам восприятия. Опирайся только на то, что проверяется на скриншоте:

1. **Один фокус.** Взгляд идёт так: «Швейное производство» → «Полного цикла под ключ» → лид → «Рассчитать стоимость» → арка. Ни один другой элемент не спорит с H1 размером, контрастом или цветом.
2. **Модульная шкала.** Соседние уровни текста различаются в 1,5–2 раза, а не на 10–20%: маленькую разницу глаз принимает за ошибку. На первом экране не больше четырёх размеров текста (главная строка H1, средняя строка H1, лид, интерфейс), не считая строки фактов.
3. **Близость.** Расстояние между группами (заголовок / лид / действия) минимум вдвое больше, чем внутри группы. Сейчас «в Челябинске» (13px) висит между строками заголовка и читается как сноска. Сделай строку заметной (16–18px моно или другое решение) и привяжи её по смыслу к «Швейное производство».
4. **Лид.** Строка 45–65 знаков, максимум 2–3 строки, без висячих «и». Не разрывай «WB / и OZON»: пиши `WB&nbsp;и&nbsp;OZON`, это одна неразрывная единица.
5. **Цифры.** Цифры цепляют взгляд раньше слов, поэтому факты пиши цифрами.
6. **Кнопка и нагрузка.** Главная кнопка — единственный залитый тёмный элемент в текстовой колонке. На экране не больше семи смысловых элементов.

Гарнитуры не меняй, их одобрили. Подобрать можно начертание дисплея (Cormorant 500 или 600: на крупном кегле 500 часто выглядит тоньше и дороже, сравни на скриншотах), трекинг и интерлиньяж.

Ориентиры размеров, px (финальные значения выбирай по скриншотам):

|---|---|---|---|---|---|

| «Полного цикла под ключ» | 52–58 | 44–48 | 38–40 | 32 | 25–26 |
| «в Челябинске», моно | 16–18 | 16 | 15 | 14 | 14 |

**Строка фактов** — единственное, что добавляется на первый экран. Три факта цифрами из texts.md: «10+ лет», «2–3 дня», «1 цех». Цифры Cormorant 36–40px, подписи моно 13px, разделители — линии 1px. Размести строку под действиями, у нижнего края экрана; на мобильном — под аркой. Если на 1366×650 строка вытесняет кнопки за край экрана, перенеси её в начало экрана 2 и напиши об этом в отчёте.

## Экран 3B — Что мы шьём (`#portfolio`)

Экран портфолио: одежда второго слоя, шесть категорий, интерактив с ощущением объёма.

- H2 и лид из texts.md.
- **Ряд-указатель:** «01 Худи и зип-худи», «02 Свитшоты», «03 Рубашки», «04 Платья», «05 Брюки», «06 Шорты». Моно, кликабельные, синхронизированы с каруселью. Активный пункт подчёркнут «строчкой» `--clay`.
- **3D-карусель (coverflow)** на CSS 3D-трансформациях, без библиотек:
  - `perspective` около 1200px. Активная карточка стоит фронтально и крупнее. Соседние повёрнуты (`rotateY` ±25–35°) и отодвинуты вглубь (`translateZ` от −120 до −200px). Дальние приглушены через `filter: brightness`.
  - Активная карточка слегка наклоняется за курсором (±4–6°), только при `pointer: fine`.
  - Управление: прямоугольные стрелки 48px, клик по соседней карточке, свайп и перетаскивание, клавиши ← →, клик по пункту ряда. Счётчик «03 / 06» моно. Автопрокрутки нет.
  - Карточка: картинка 3:4 (слоты 04–09), номер в углу оформлен как бирка с пунктиром, будто вшитый ярлык, название Cormorant 28–32px. На активной карточке кнопка «Рассчитать» ведёт в калькулятор с выбранным изделием.
  - Мобильный: одна карточка по центру и края соседних, 3D мягче (±15°), свайп.
  - `prefers-reduced-motion`: плоский горизонтальный ряд со scroll-snap, без поворотов.
  - Доступность: у контейнера `role="region"` и `aria-roledescription="карусель"`. У слайдов `aria-label` вида «3 из 6: Рубашки». Неактивные слайды выпадают из порядка табуляции. Счётчик объявляется через живой регион.
  - Объём создают только перспектива, масштаб и затемнение. Без глянца, бликов, «стекла» и теней с размытием: система плоская.

## Экран 5 — От идеи до реализации (`#raschet`)

H2 и лид из texts.md. Под ними строка пути из пяти шагов: бейджи `.step-n` из v1, соединённые пунктиром. На мобильном путь идёт вертикально и компактно.

Ниже калькулятор. По сути это квиз из четырёх шагов, а не калькулятор цены: цен в брифе нет, и расчёт посетитель получает после того, как оставит контакты (бриф, п. 7). В брифе спрашивали, не нужно ли два калькулятора. Одна форма с выбором направления закрывает этот вопрос: разные цены — это разные направления внутри одной формы.

**Раскладка:** слева шаги (7–8 колонок), справа панель «Ваш проект» (4 колонки), она обновляется вживую. На ≤959px панель сворачивается в строку-итог над кнопкой «Далее».

Шаги, поля, подсказки, ошибки и текст успеха берёшь из texts.md. Правила:

- Прогресс: «Шаг 2 из 4» и тонкая полоса с делениями, как у сантиметровой ленты (продолжение мотива ленты).
- Кнопки «Назад» и «Далее». «Далее» не блокируется молча: если обязательное поле пустое, у поля появляется понятная ошибка.

## Техника: что изменилось с v1

- В v1 ради Zero Block были запрещены скролл-эффекты и сложный интерактив. В v2 три модуля выходят за возможности Zero Block: калькулятор, карусель и список задач. Делай каждый изолированным: свой класс-префикс (`kc-calc`, `kc-carousel`, `kc-tasks`), свой блок CSS и JS без глобальных зависимостей. Так каждый модуль можно вставить в Тильду HTML-блоком (T123). В README — инструкция переноса для каждого.
- Остальное как в v1: размеры в px по брейкпоинтам Тильды (1200 / 960 / 640 / 480 / 320), без vw в типографике, без появления блоков при прокрутке, одна анимация загрузки на первом экране.
- Движение только в модулях и на ховерах: 150–300 мс, `ease-out`, без пружин и прыжков. При `prefers-reduced-motion` всё статично.
- Типографика: `lang="ru"`; неразрывные пробелы после коротких слов, в «300 ед.», «2–3 дня» и в телефоне; кавычки «ёлочки»; буква ё; `text-wrap: balance` для заголовков.
- Доступность: контраст не ниже AA, видимый фокус, цели нажатия от 44px, alt на русском. Всё интерактивное работает с клавиатуры.
- Производительность: слот 01 с `fetchpriority="high"`, остальные с `loading="lazy"`. В консоли 0 ошибок. Lighthouse ≥90 как ориентир.
- Мета: title прежний, description из texts.md.
