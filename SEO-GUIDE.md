# SEO-слой сайта «Культура шитья»

Как устроена автоматизация, как её запускать и что нужно сделать до выкладки. Все команды — из корня проекта.

## Идея

Тексты, адреса, мета-теги и разметка не правятся руками в HTML. Они лежат в данных, а страницы, `sitemap.xml`, `robots.txt`, 404 и юридические страницы собирает скрипт. Проверяет результат другой скрипт. Так новая страница или правка заголовка не ломает карту сайта, хлебные крошки, перелинковку и разметку.

```
seo/semantics.xlsx ──npm run seo:import──▶ seo/semantics.json ─┐
seo/site.json  (факты о компании)                              ├─ npm run seo ─▶ страницы, sitemap.xml, robots.txt, 404,
seo/pages/*.json (тексты, FAQ, ключи, объявления)               │                  privacy/, consent/, вставки в index.html
seo/home.json (FAQ и title главной)                             │
seo/reviews.json, seo/cases.json (только настоящие)             ┘
                                                    npm run seo:audit ─▶ ошибки и предупреждения
                                                    npm run seo:direct ─▶ seo/direct/direct-ready.xlsx
                                                    npm run seo:og ─▶ assets/og/<страница>.jpg (1200×630)
```

## Команды

| Команда | Что делает |
|---|---|
| `npm run seo` | Собирает страницы и SEO-файлы из данных |
| `npm run seo:check` | Ничего не пишет, падает, если файлы устарели относительно данных |
| `npm run seo:audit` | Проверяет собранный сайт (ниже). Ошибки роняют команду, предупреждения только печатаются |
| `npm run seo:release` | То же, но каждая метка `[уточнить]` на странице считается ошибкой. Запускать перед выкладкой |
| `npm run seo:import` | Перечитывает `seo/semantics.xlsx` в `seo/semantics.json` (после того как SEO-специалист обновил книгу) |
| `npm run seo:og` | Перерисовывает картинки для соцсетей (после смены заголовков или фото страниц) |
| `npm run seo:direct` | Собирает `seo/direct/direct-ready.xlsx` и `phrases.csv` для Директа |
| `npm run preview:page` | Один HTML-файл с внутренней страницей `/opt/` для просмотра без сервера |

После правки данных: `npm run seo`, затем `npm run seo:audit`. Если менялись заголовки H1 или фото страниц, ещё `npm run seo:og`.

## Что в данных

- **`seo/site.json`** — факты: телефон, адрес, основатель, мессенджеры, соцсети, срок ответа, часы работы, номер счётчика Метрики, реквизиты. `null` значит «данных нет»: скрипт показывает метку `[уточнить]` и ничего не выдумывает. Когда значение заполнено, оно попадает в разметку, подвал, политику и JSON-LD.
- **`seo/pages/<slug>.json`** — страница: ключевая фраза и дополнительные, лид, факты, блоки текста (`text`, `list`, `steps`), FAQ из пяти вопросов, связанные страницы, объявления для Директа. `title`, `description` и `h1` по умолчанию берутся из листа «Страницы SEO» семантики; поле в JSON перебивает их (так сделано для `dtf-pechat`, `lekala-konstruktor`, `platya-rubashki-bryuki`: основной ключ должен быть в title и H1).
- Ссылки внутри текста пишутся как `[текст](/slug/)`: скрипт проверяет, что страница существует. Неразрывные пробелы и тире расставляются сами.
- **`seo/reviews.json`** — отзывы. Формат: `{"author": "Имя", "company": "…", "text": "…", "date": "2026-10-01", "rating": 5, "source": "https://…", "published": true}`. Блок и разметка `Review` появляются на страницах только для записей с `published: true`. Отзывы нужны настоящие: лучше подключить виджет карточки в Яндекс Бизнесе и брать оттуда.
- **`seo/cases.json`** — кейсы. Формат: `{"title": "…", "task": "…", "solution": "…", "result": "…", "date": "2026", "images": [{"src": "assets/img/…", "alt": "…", "w": 1200, "h": 800}], "published": true}`. Пока нет ни одного опубликованного кейса, страницы `/keysy/` нет. С первым появляются страница, ссылка в подвале и запись в `sitemap.xml`.

## Что собирается

- **Страницы:** `/uslugi/` (каталог) и 12 страниц по кластерам семантики. На каждой: хлебные крошки (с разметкой), H1, лид, кнопка «Рассчитать …» с предвыбором в квизе, «Скачать прайс», телефон, срок ответа, факты, текст, «Смотрите также», FAQ, квиз, финальная полоса, липкая кнопка на мобильном.
- **Разметка:** `LocalBusiness` (адрес, телефон, основатель, каталог услуг, области обслуживания), `WebSite`, `WebPage`, `Service`, `BreadcrumbList`, `FAQPage`. Разметка вопросов и ответов совпадает с видимым текстом (аудит это проверяет). `AggregateRating` и выдуманные отзывы запрещены.
- **Главная:** title и description из семантики, FAQ из пяти вопросов в конце квиза, блок «Услуги и изделия» в подвале, контекстные ссылки в тексте.
- **Файлы:** `sitemap.xml` (только индексируемые страницы, `lastmod` из истории git), `robots.txt` (с `Clean-param` для меток `utm_*`, `yclid`, `ysclid`), `404.html` (с `noindex` и ссылками на разделы), `privacy/` (индексируется), `consent/` (`noindex`).
- **Картинки:** у каждой страницы своя картинка для соцсетей, у всех фото описательный `alt`, у картинок заданы `width` и `height`.

## Что проверяет аудит

Title (≤ 70, уникален) · description (≤ 160, уникален) · один H1, уникальный · порядок заголовков · canonical · Open Graph и размер картинки 1200×630 · `alt` у каждой картинки · JSON-LD разбирается, нужные типы есть, крошки и FAQ совпадают с видимыми · битые внутренние ссылки и якоря · сироты (на страницу ведёт меньше трёх ссылок, нет ссылки с главной) · sitemap и robots · 404 · основной ключ в title+H1 и в тексте, покрытие дополнительных, переспам · похожесть текстов между страницами · объём текста · блок кнопок, квиз, телефон, липкая кнопка.

## Яндекс Метрика и цели

1. Создать счётчик в Метрике для домена, записать номер в `seo/site.json` → `metrikaId`, выполнить `npm run seo`.
2. Скрипт `analytics.js` подключит счётчик (вебвизор выключен: в формах вводят телефон), покажет уведомление о cookie и начнёт отправлять цели. На локальных адресах внешний скрипт не грузится.
3. В Метрике создать цели типа «JavaScript-событие» с идентификаторами: `calc_submit`, `callback_submit`, `price_submit`, `price_download`, `phone_click`, `messenger_click`, `cta_click`, `calc_start`, `price_open`. Для оптимизации Директа брать `calc_submit`, `callback_submit`, `phone_click`, `messenger_click`.
4. Google Analytics не подключён: передача данных за рубеж требует отдельного уведомления Роскомнадзора, а для российской аудитории Метрики достаточно. Если нужен, добавляется отдельным скриптом после юриста.

## Перед выкладкой

1. Заполнить `seo/site.json`: `legal` (наименование, ИНН, ОГРН, адрес, e-mail, ответственный), `address.street`, `email`, `responseTime`, `hours`, мессенджеры, `metrikaId`. Сменить `domain`, если домен другой.
2. Показать тексты `privacy/` и `consent/` юристу (сейчас это проект, баннер на странице это говорит) и убедиться, что утверждения политики верны: хостинг и CRM в РФ, соединение по HTTPS, список получателей данных.
3. Заменить временные AI-фото слотов 04–09 и подтвердить права на остальные фото (`CREDITS.md`).
4. `npm run seo && npm run seo:og && npm run seo:release` — должно быть без ошибок.
5. Настроить сервер по `seo/nginx.conf.example`: адреса со слэшем, редирект с `www` и http, страница 404, сжатие, кэш.
6. Яндекс Вебмастер и Google Search Console: подтвердить домен, загрузить `sitemap.xml`, в Вебмастере указать регион «Челябинск». Яндекс Бизнес: карточка компании с адресом и телефоном (то же название и телефон, что на сайте).
7. Метрика: цели выше, проверить в отчёте «Реальное время», что события приходят.
8. Директ: загрузить структуру из `seo/direct/direct-ready.xlsx`, включить разметку ссылок для Метрики.

## Ограничения и решения

- **Скрытого текста нет.** Вопросы FAQ свёрнуты, но целиком лежат в разметке и совпадают с разметкой `FAQPage`: так можно и показывать пользователю, и отдавать поисковикам. Текст, видимый только роботу, считается маскировкой и ведёт к санкциям.
- Расширенный сниппет с FAQ в Google для обычных сайтов почти не показывается, а в Яндексе поддерживается: разметка остаётся ради Яндекса и ИИ-ответов.
- Отзывы, кейсы и фото команды в данных не выдуманы: без исходных материалов блоки не появляются. Список материалов — в `REPORT-v8.md`.
- Сайт собран статически. В Тильде этот слой переносится так: метаданные и `JSON-LD` — в настройки страницы и HTML-блок T123, `sitemap.xml` Тильда делает сама, `robots.txt` редактируется в настройках сайта, 404 настраивается отдельной страницей.
